       1| # Heartbeat Feature Design Specification
       2| 
       3| ## 1. Overview
       4| A heartbeat mechanism to ensure the synchronization between the VS Code Extension (Backend) and the Webview (Frontend). It serves two purposes:
       5| * **Module Synchronization**: Allows other extension modules to react to a periodic "tick" event.
       6| * **Connection Monitoring**: Provides a visual "heartly light" in the WebUI to indicate that the extension process is alive.
       7| 
       8| ## 2. Architecture
       9| 
      10| ### A. Backend: `HeartbeatService` (Singleton)
      11| - **Interval**: Every 5 seconds.
      12| - **Observer Pattern**:
      13|     - `onTick(callback: () => void): Disposable`: Allows modules to subscribe to the heartbeat event.
      14|     - `start()` / `stop()`: Controls the execution of the `setInterval`.
      15| - **Broadcaster**:
      16|     - `broadcastToWebview(panel: OllamaChatPanel)`: Sends a `postMessage` containing `{ type: 'heartbeat', timestamp: Date.now() }` to the active Webview.
      17| 
      18| ### B. Frontend: WebUI Heartbeat Light
      19| - **UI Element**: A small circular `<span>` (the "light") placed in the `#topBarPrimary`.
      20| - **Visual States**:
      21|     - **Green (`#4ec994`)**: Received a message within the last 10 seconds.
      22|      overlap with heartbeat interval.
      23|     - **Red/Dim (`rgba(255,0,0,0.5)`)**: No message received for $>10$ seconds (indicates extension stall).
      24| - **Logic**: A `setInterval` in the Webview script monitors the delta between `Date.now()` and the last received heartbeat timestamp.
      25| 
      26| ## 3. Implementation Plan
      27| 1. Create `src/services/HeartbeatService.ts`.
      28| 2. Update `src/ollama-chat.ts` to subscribe and broadcast.
      29| 3. Update `src/webview/WebviewRenderer.ts` with CSS, HTML, and JS logic.
